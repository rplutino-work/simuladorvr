⚠ Acción requerida

Tres cosas que conviene resolver antes de publicar el manual. Las dos primeras son fixes de código/config rápidos; la tercera es una decisión.

Crítico · bug
El código de un grupo no funciona en la tablet

La tablet valida solo el campo code, y las reservas de grupo lo tienen en groupCode (con code = null). Un cliente de grupo online paga, recibe el código por email, pero al ingresarlo en la tablet obtiene "Código inválido". Hoy los grupos solo arrancan desde el panel con "Iniciar grupo ahora". Rompe el flujo de grupo online de punta a punta. → Recomendado: que /api/tablet/activate acepte también groupCode.

Config
El horario configurado no coincide con el del local

El sistema tiene closeHour = 23 en la base, pero el local atiende 10 a 20. La web ofrece turnos hasta las 23. → Cambiar la hora de cierre a 20 en Configuración.

A tener en cuenta
Los permisos son más laxos de lo esperado

Solo precios, configuración y puestos son exclusivos de ADMIN. Un Operador puede confirmar pagos, cancelar y reembolsar vía API. Decidir si se restringe o queda así.

01 Acceso, usuarios y roles

  • Login y redirección: URL /admin/login. Cualquier /admin sin sesión redirige ahí; tras entrar va al Dashboard (/admin). middleware.ts:144
  • Roles: ADMIN y OPERATOR (no hay un tercero). Se ven como "Administrador" / "Operador". schema.prisma:28
  • Permisos: solo puestos, settings y email-test validan rol ADMIN en el backend; el resto de acciones admin solo exigen sesión iniciada. (Ver tabla de permisos.)
  • Alta de usuarios / reset de contraseña: NO EXISTE pantalla ni recuperación. Se crean por base/seed. prisma/seed.ts:8
  • Duración de sesión: 24 horas. lib/auth.ts:62

02 Estructura del panel

Menú lateral app/admin/layout.tsx:28

  • Grupo "General": Dashboard → /admin · Reservas → /admin/reservas · Métricas → /admin/metricas
  • Grupo "Gestión" (oculto al operador): Simuladores → /admin/puestos · Configuración → /admin/configuracion

Dashboard

KPIs: Reservas activas, Ingresos hoy (vs ayer), Ingresos del mes, Reservas hoy (vs ayer). Gráficos: Ingresos 14 días · Uso por simulador · Duración elegida · Estado de reservas · Actividad por hora (30 días). Todo en hora Argentina.

Estado de dispositivos (solo Dashboard)

Heartbeat del kiosko cada 15 s; el panel refresca cada 5 s; se marca offline a los 45 s. Estados: Online Offline Sin señal En sesión (la TV cuando está en HDMI de la PlayStation). app/admin/page.tsx:32

03 Pantalla de Reservas

  • Columnas: Código · Simulador · Cliente · Inicio · Dur./$ · Estado · Acciones.
  • Filtros: buscador único de texto ("Código, nombre o email…") + filtro por estado. No hay filtro por fecha ni por puesto en la UI.
  • Editar/reprogramar: desde el panel solo se cancela y recrea (se editan notas/nombre/email, no fecha/hora). La reprogramación real es self-service del cliente con su token.
  • Código y reenvío: el código se muestra y se copia; no hay botón de reenviar email.
Ojo
"Iniciar sesión" individual desde el panel no funciona

El backend lo rechaza a propósito ("ingresá el código en la tablet…") y el front no muestra el error. Las sesiones individuales arrancan solo desde la tablet. Solo los grupos se inician desde el panel.

04 Walk-in (cliente sin reserva)

  • Botón: "Walk-in / Efectivo" → modal "Reserva manual (walk-in)".
  • Campos: Simulador y Fecha y Hora obligatorios; Duración (30/60/120, default 60); Nombre, Email, Notas opcionales; checkbox de enviar email (solo si hay email).
  • Cobro: queda Pagado al instante. No se elige monto (toma el del puesto) ni medio de pago (se asume efectivo).
  • Código/email: genera código siempre; email solo si se tildó y hay email.
  • "Ahora mismo": se crea con hora actual pero no arranca solo — la sesión corre al ingresar el código en la tablet.

05 Grupos

  • Modelo: no hay tabla Group. Un grupo = varias reservas con el mismo groupId y groupCode compartido. schema.prisma:136
  • Carga: botón "Grupo" → modal "Reserva grupal". Elegís 2+ puestos, una duración, fecha y hora → "Crear grupo · $…". Crea N reservas Pagadas.
  • Iniciar: "Iniciar grupo ahora" pone todas las sesiones en curso de una. También finalizar/cancelar el grupo entero.
  • Código: uno solo compartido. No se valida en la tablet (ver Acción requerida).
  • Cancelar un puesto: no recalcula el descuento ni cambia el código.
  • Duraciones: todas iguales dentro del grupo.

06 Descuento por grupo

  • Config: tabla BusinessSettings, editable desde Configuración. schema.prisma:53
  • Tramos por defecto: 2 → 5% · 3 → 10% · 4 → 15% · 5 → 20%. Para 6+ toma el tramo más alto ≤ cantidad.
  • Aplica igual a 30/60/120; redondea al centavo, el resto va a la primera reserva.
  • Fechas: vacías = siempre; fuera del rango = 0%.
  • Panel: los grupos walk-in también reciben el descuento.
  • Desactivado: no se muestra el aviso "¿Vienen en grupo?" y se paga el total sin rebaja.

07 Código de acceso

  • Formato: 4 caracteres, alfabeto ABCDEFGHJKLMNPQRSTUVWXYZ23456789 (sin O, 0, I, 1). el comentario del código dice "6-digit" — está obsoleto
  • Se genera al confirmar el pago, no al crear la reserva.
  • Validez: no vence por tiempo — se canjea cuando el puesto está libre. La sesión ya iniciada se cierra sola 5 min después de su fin.
  • Reuso: reingresar mientras está en curso retoma la sesión (no reinicia). Finalizada ya no sirve.
  • Intentos: 15 cada 5 min por IP+puesto (sin bloqueo permanente).
  • Unicidad: el código individual es único para siempre; el de grupo se puede repetir otro día.

08 Tablets, TVs y sesiones

  • App: WebView nativa Android (Capacitor) que abre la web de Vercel. Dos APKs (tablet y TV). El modo kiosko efectivo (Device Owner/MDM) es config del dispositivo, fuera del repo.
  • Vínculo tablet→puesto: por URL (/tablet/1) y/o memoria local. Sin login ni QR.
  • Encendido de la pantalla: la tablet marca la sesión activa; la TV lo detecta por polling y cambia a la entrada HDMI de la PlayStation.
  • Cierre: al llegar a 0 la tablet cierra la sesión; red de seguridad por cron con 5 min de gracia.
  • Corte de internet: la tablet sigue contando localmente; el retorno del HDMI está garantizado por alarma nativa.
  • Reinicio: apagar/prender la devuelve sola a la app. La re-vinculación por ADB no está en el repo (runbook de flota).
  • Desactivar un puesto con sesión activa: la sesión en curso no se corta; bloquea nuevos inicios.

09 Disponibilidad y horarios

  • Generación: slots de apertura a cierre cada slotInterval min (defaults 10 / 20 / 15).
  • Reservas sin pagar: bloquean el horario; expiran a los 30 min, liberadas por el cron (cada 5 min), no al consultar.
  • Zona horaria: Argentina UTC-3 fijo, sin horario de verano.
  • Bloquear feriados / franjas / mantenimiento: NO EXISTE.
  • 120 min: habilitado en la web (requiere price120 > 0).
  • Anticipación máxima: sin tope.

11 MercadoPago

  • Integración: Checkout Pro (redirección). Sin restricción de medios; moneda ARS.
  • Confirmación: webhook + polling + cron. "Pagado" = approved, con guardia de pago insuficiente.
  • Reconciliación: cron cada 5 min (Vercel) + 10 min (GitHub Actions): recupera pagos con webhook perdido (incluye grupos), expira pendientes, cierra sesiones vencidas.
  • Pago tras expirar: no revive solo → pago huérfano → reembolso manual.
  • Reembolsos: desde el panel ("Reembolsar y cancelar"). Lo puede usar cualquier usuario logueado.
  • ID de pago: en el detalle de la reserva, sección "Pago".

12 Emails

  • Servicio: Resend. Remitente configurable (fallback Race Room <onboarding@resend.dev>).
  • Emails que envía: uno solo — confirmación, asunto ✅ Reserva confirmada – Código {code}. No hay recordatorio, cancelación ni reembolso.
  • Reenvío: no hay botón (solo un "email de prueba" que manda TEST01).
  • Email mal escrito: se puede corregir, pero no se reenvía automáticamente si ya tiene código.

13 Configuración

  • Cierre ≤ apertura: aviso en vivo y rechazo del servidor — no se puede guardar un horario invertido.
  • Cancelaciones: Manual = marca cancelada + WhatsApp (no devuelve plata); Automático = además reembolsa por MP (el efectivo siempre cae a Manual). El cliente cancela desde el link del email.
  • Interruptor de emails: global.
  • Cache: se invalida al guardar (settings 30 s / puestos 60 s de respaldo).

La tabla completa de campos está en Tablas de referencia.

14 Puestos

  • Cantidad: no fija — hay botón "Nuevo simulador".
  • Campo VR: NO EXISTE en el sistema (dato manual: 4 y 5).
  • Nombres: "Simulador 1"…"Simulador 5".
  • Desactivar: desaparece de la web y la disponibilidad; sigue en el admin como "Inactivo"; las reservas ya vendidas no se tocan y se pueden seguir activando.

15 Errores

Página de estado / "sistema caído": NO EXISTE. Los logs se ven en Vercel (Runtime Logs) y el cron en GitHub Actions; no hay Sentry/Datadog. Los textos literales de error de la tablet están en Tablas de referencia.

16 Infraestructura

  • Hosting: app en Vercel, base en Neon Postgres (us-east-1). Dominio raceroom.com.ar. El registrador/DNS no está en el repo.
  • Backups: no en el repo; dependen de Neon.
  • Tareas programadas: un job (expire-bookings) con dos disparadores (Vercel */5 + GitHub Actions */10): reconcilia pagos, expira pendientes, auto-finaliza sesiones vencidas.
  • Encendido/apagado: seguro apagar/reiniciar — el sistema se auto-cura. No requiere apagado ordenado.

Lo que el manual dice mal (supuestos vs. código)

  • El código de acceso es de 4 caracteres, no 6.
  • Crítico: el código de grupo no funciona en la tablet (ver arriba).
  • "Iniciar sesión" individual desde el panel falla en silencio.
  • Permisos más laxos: el Operador puede confirmar/cancelar/reembolsar.
  • No hay pantalla de usuarios ni recuperación de contraseña.
  • No existen: filtro por fecha/puesto, reprogramar desde el panel, reenviar email, emails de recordatorio/cancelación, bloqueo de feriados, tope de anticipación, campo VR, precios por día/horario, página de estado, backups en el repo.
  • Walk-in: no se elige monto ni medio de pago.
  • El código de grupo no es único para siempre; el individual sí.
  • Horario: el sistema tiene cierre a las 23, el local cierra a las 20.
  • 90 min existe en la base pero no se ofrece para venta.
